# 小游戏｜街机漫画 HUD 后续制作指引 v0.1

确认日期：2026-08-23

适用范围：篮球、乒乓球、跳远、爬竹竿，以及后续获用户视觉确认的跳房子、踢毽子、抓石子和弹弓的常驻成绩、过程反馈与高潮庆贺

视觉基准：`docs/previews/minigame-arcade-comic-ui-v01/celebration-style-approved-v01.png`

实现记录：`docs/reports/minigame-arcade-comic-hud-runtime-v0.2.md`

## 1. 核心美术语言

- 方向是“八十年代街机标题 × 动作漫画爆字”，不是细线 8-bit 点阵字，也不是 LCD 掌机字。
- 主字面使用金黄／暖橙，加入块状白高光、红色近影和深钴蓝厚影；轮廓可以保留烘入画面的像素阶梯。
- 字形应粗、重、略倾斜，并允许局部挤压和拉伸；不能因为追求像素感而变得单薄。
- 常驻数字、普通大字和高潮爆字属于同一家族，但强度不同。不能把每条文字都做成全屏爆炸。
- 这一风格只用于四项小游戏的比赛信息，不扩展到行走、拾取、教学、场景交互或两台 LCD 掌机。乒乓球的“比赛／退出”是已确认例外：使用同系黄底、红影、蓝色点缀按钮，但不使用爆炸后景。

## 2. 三个视觉等级

### L1：常驻成绩

用于比分、距离、高度、命中和投篮次数。只显示标签与可组合数字，不使用放射线；数值变化只做约 180ms 的轻微弹跳。

桌面横屏参考高度：

| 游戏 | 主数字 | 次数字 |
| --- | ---: | ---: |
| 篮球 | 总分 156px | 命中／投篮 96px |
| 乒乓球 | 双方比分 156px | — |
| 跳远 | 距离 280px | — |
| 爬竹竿 | 高度 140px | 本次增量 120px |

手机竖屏参考高度：篮球 70／50px、乒乓球 60px、跳远 144px、竹竿 92／84px。以上是当前已确认布局的下限参考；后续调整不得悄悄退回上一版的小字，也不得简单整体缩放导致裁切。

### L2：普通漫画大字

用于需要被玩家立即看见、但不构成得分高潮的反馈。只显示前景短语，使用克制的弹性放大；不得显示放射线、星芒、碎裂线或像素碎片。

当前曲线：`0.58× → 1.10× → 0.97× → 1.00×`，不延迟启动，最终整体约为完整庆贺文字的 `0.92×`。持续时间通常为 0.8–1.0 秒。

### L3：完整高潮庆贺

只用于实际得分或明显优秀成绩。前景文字和后景爆炸线必须是两个独立 WebGL Sprite，使用不同中心、起始时间、旋转和回弹周期。

- 后景：`0.35× → 1.25× → 0.96× → 1.00×`，稳定后继续外扩并淡出；
- 前景延迟约 50ms：`0.20× → 1.35× → 0.92× → 1.08× → 1.00×`；
- 总时长约 0.8–1.1 秒；
- 后景不能与文字烘成一张图，不能用完全同步缩放冒充分层动画。

## 3. 当前事件映射

| 游戏事件 | 文字 | 等级／后景 |
| --- | --- | --- |
| 篮球命中 | `两分球！／三分球！／四分球！` | L3 `major` |
| 乒乓球玩家得分 | `得分！` | L3 `hit` |
| 乒乓球普通回球 | `好球！` | L3 `hit`；与扣杀互斥，覆盖顶部中央比分位置 |
| 乒乓球扣杀 | `扣杀！` | L3 `hit`；优先于好球，不叠加第二行文字 |
| 乒乓球玩家获胜 | `赢啦！` | L3 `major` |
| 乒乓球玩家落败 | `再来！` | L2，无后景 |
| 乒乓球电脑普通得分 | 无大字，只更新比分 | L1 |

普通回球的“好球！”不是逐拍反馈：每次有效非发球回球仅有 30% 概率触发，并设置 2.4 秒冷却；扣杀不参与抽样，始终优先显示“扣杀！”。
| 跳远离板 | `跳！` | L2，无后景 |
| 跳远 2.00m 及以上 | `跳得真远！` | L3 `major` |
| 跳远 1.60–1.99m | `不错！` | L2，无后景 |
| 跳远 1.30–1.59m | `再来一次！` | L2，无后景 |
| 跳远 1.30m 以下 | `再用点力！` | L2，无后景 |
| 跳远越线 | `用力过头啦！` | L2，无后景 |
| 竹竿普通上升 | `抓稳！` | L2，无后景 |
| 竹竿完美蓄力 | `用力！` | L3 `hit` |
| 竹竿脱手 | `脱手！`＋较小的`再试！` | L2，无后景 |
| 竹竿到顶 | `到顶啦！` | L3 `major` |
| 弹弓命中积木 | `命中！` | L3 `hit` |
| 弹弓弹丸落定、超时或离开安全靶道 | `没打中` | L2，无后景 |

`fail` 后景资源目前保留在共享图集中，但没有映射到普通失败。以后只有当失败本身是需要戏剧化表现的特殊事件，并经过视觉确认后，才允许启用；不能因为资源已经存在就自动使用。

## 4. 文字与数字规则

- 篮球命中只报告分值，不再显示或叠加“进啦！”。
- 中文短语按完整构图制作，不把庆贺文字拆成任意单字组合。
- 标题短语与爆炸后景必须保持图集原始宽高比，只允许整体等比缩放；安全区不足时缩小整层，不得单独拉宽或压扁任一轴。
- 只有 `0–9` 与 `+ - : / . %` 在运行时组合；所有数字固定字宽、统一基线和阴影安全区，`1` 做视觉补宽。
- 数字位数变化不能引起整个比分左右跳动；红影和蓝影不能被相邻 UV 或面板边缘截断。
- 所有游戏内中文使用简体中文。标签、数字与短语必须在明亮水泥、深树影和室内暗墙三类背景上保持清晰。

## 5. 布局与安全区

- 比分可以扩大面板，但不能遮挡球、球拍、篮圈、踏板、竹竿目标、退出按钮或触摸操作区。
- 桌面横屏、手机横屏和手机竖屏分别排版；禁止只按桌面坐标等比缩小。
- 跳远竖屏允许将“距离”、数字和“米”分层排布，以保证 144px 主数字不裁切。
- 大字反馈应位于主要视线区，但 L2 不能因尺寸大就被误认为 L3；判断依据是有没有独立爆炸后景，而不是文字是否醒目。
- 大字和比分同时存在时，保持层级清楚；大字短暂覆盖局部成绩面板可以接受，但不得挡住正在进行的操作目标。
- 乒乓球固定为左上“比赛”、顶部中央大比分、右上“退出”；好球、扣杀、得分和赛果短暂覆盖中央比分位置，不另占一条提示带。

## 6. 资源与运行时边界

- 共享一张数字／标点／标签图集和一张无字后景图集；每项游戏各有一张按首次进入加载的短语图集。
- 高分辨率素材将像素阶梯烘入画面，运行时使用线性过滤与 mipmap；不要改用 `NearestFilter` 制造缩放抖动。
- 所有 Sprite、几何、材质和字形槽在加载阶段建立。热路径只更新 UV、transform、opacity、visibility 和 uniform。
- 得分或反馈瞬间不得创建 CanvasTexture、纹理、材质，也不得设置 `material.needsUpdate`。
- 四个玩法控制器只发送语义事件，不互相引用，也不复制动画实现。
- 后续玩法控制器同样只发送各自语义事件；弹弓的命中映射为 L3 `hit`，落空映射为无后景 L2，不能因“没打中”也是大字就启用放射线。
- 新增短语前先确认它属于 L1、L2 还是 L3；只有 L3 才能分配 `major` 或 `hit` 后景。

## 7. 修改与验收清单

每次修改至少检查：

1. 数字 `0、1、9、10、99、100、999` 的固定宽度、UV、基线和阴影；
2. 篮球 2／3／4 分、乒乓球玩家／电脑得分与胜负、跳远全部区间、竹竿普通／完美／脱手／到顶；
3. L2 的 `burstVisible` 必须为 `false`，L3 的文字与后景启动和缩放必须独立；
4. 退出玩法后清理大字、后景、计时器和当前玩法文字图集状态；
5. 三种屏幕方向的裁切、遮挡与触摸安全区；
6. `npm run build`、`npm run perf:build`、需要测试 API 时的 `npm run build:test` 及相关定向测试。

未获用户确认前不得批量扩展未经确认的新字形方向，也不得更新视觉截图基线。
