# 混合行走控制方案 v0.2

日期：2026-08-22

## 最终交互结论

自由行走与定位行走不是互斥模式，而是普通第一人称 `walk` 状态下同时存在的两套输入：

- 桌面端始终保留 WASD、方向键、Shift 和鼠标环视。
- 触屏始终保留左侧摇杆和单指拖动环视。
- 玩家看向可达地面时显示荧光绿定位标记；点击或轻触即可自动走向该点，操作文字只在底部状态栏显示。
- 自动行走期间仍可环视；一次点击／轻触只停止，移动键或摇杆会立即接管。
- 任一 WASD 或方向键按住期间隐藏并暂停定位候选；全部移动键松开后恢复查询，避免键盘行走时标记晃动干扰视线。
- 不显示进入场景时的操作方式选择纸，不保存操作方式，不显示右下切换按钮。

定位行走只在普通第一人称行走中工作；鸟瞰、坐下、文档、黑板、乒乓球、竹竿和掌机等状态会停用并清除自动目标。手持篮球时仍可定位；有有效地面目标时点击优先行走，没有目标时才按投篮处理。

## 桌面鼠标锁定兼容（2026-09-06）

- 浏览器暴露 Pointer Lock API 但首次请求被异步拒绝，或 1.5 秒没有完成时，自动启用已有拖动环视。WASD、方向键和绿色标记点击行走继续可用。
- 直接接收原生 `requestPointerLock()` 的 Promise，避免 Three.js `lock()` 不返回 Promise 导致拒绝未被捕获。成功后的视角控制仍由 Three.js 接管。
- 已成功锁定过的浏览器在 Esc 后暂时重锁失败时保留点击重试；加载阶段就失败也会把回退状态带入漫游。迟到的成功事件会退出拖动模式。
- 回归命令：`npx playwright test --config playwright.controls.config.js`。该专项使用普通开发入口，避免 `build:test` 跳过锁鼠标而漏检真实键盘移动。

## 目标选择

中央准星候选必须同时满足：

- 镜头俯角至少 4°；平地视线可覆盖 20 米，再由距离上限截断。
- 水平距离为 0.45–20 米。
- 最近命中面属于数值导航地形、台阶、连续楼梯斜面、坡道、平台或楼层可行走面。
- 终点可容纳玩家，且以现有碰撞规则模拟的直线路径可达。
- 当前准星没有命中优先级更高的篮球、粉笔、掌机、文档、黑板、座位、门窗或玩法入口。

原始落点位于 0.45–20 米范围内但被障碍占用或直达失败时，只取得定位光标半径 1 米内的局部碰撞体和导航面，并在其中搜索最多偏移 0.8 米的合法落脚点；剩余 0.2 米用于玩家碰撞半径。搜索优先尝试视线左右两侧的通道，再尝试玩家一侧和远侧；候选仍须满足同层高度、玩家半径占位、20 米距离和完整直达路径校验。该容错用于门口、楼梯边缘、走廊及课桌间通道，不允许把范围外目标吸回范围内，也不允许越墙、跨层或绕墙寻路。

求交直接使用 `player-navigation` 的数值可行走面，不递归射线扫描完整 Three.js 场景。普通地形以高度函数迭代求交；楼梯、坡道和平台与其数据平面直接求交，再选择离相机最近的导航表面，避免多层地面选错层。

首版不做绕墙寻路。楼梯沿现有结构逐段定位：下跑、转角平台、上跑和到达平台都可成为目标；实际移动继续逐级踏步，不穿墙或直接抬升到楼层。

## 自动移动

- 确认后保存固定世界坐标，移动方向与镜头方向解耦。
- 使用普通步速，并继续调用 `navigation.move()`。
- 实际移动与路径预检共用 0.08 米子步、碰撞、抬步、楼梯、坡道和地面高度规则。
- 距离目标 0.25 米时到达。
- 连续约 450 ms 没有有效位移时停止并提示“这里走不过去”。
- 到达、阻挡、键盘、摇杆、鸟瞰、坐下、玩法进入、文档打开、失焦、页面隐藏或 Pointer Lock 丢失都会清理目标。

## 触摸判定

- `pointerdown` 只记录手势，只有 `pointerup` 才能产生轻触。
- 单指累计移动超过 10 CSS px 后永久视为环视拖动，即使回到起点也不恢复为轻触。
- 多点触摸、`pointercancel`、窗口失焦和视口变化取消轻触候选。
- 自动行走期间拖动只环视，合法轻触才停止。
- 静止轻触先执行场景互动；未命中互动且定位候选有效时才开始自动行走。
- 左侧摇杆始终显示；开始摇杆输入会取消自动目标并转为手动移动。

## 视觉

- 世界定位标记只使用单层透明荧光绿圆环与单层透明荧光绿定位针，不叠加第二层渐变或辉光，也不在世界标记上显示文字。
- 标记仅在视觉上沿玩家方向前移最多约 1.15 米，实际导航目标仍是准星命中的地面坐标，避免图标与中央准星重叠。
- 底部 WebGL 状态栏显示“点击前往 · 再次停止／轻触前往 · 再次停止”；自动行走到达或停止不播放铃声。
- 资源在场景加载阶段创建并预热；热路径只更新可见性、transform 和 opacity。
- 不新增场景内 HTML 浮层，不使用普通 HUD 像素风，不更新现有截图基线。

## 玩家帮助与教学

- 正式帮助页单列“混合行走”，说明键盘／摇杆与定位行走同时存在、20 米范围、途中环视、点击停止、手动输入接管和狭窄位置吸附。
- 桌面说明包含方向键、按键期间隐藏定位标记，以及手持篮球时绿色定位优先于投篮。
- 触屏说明区分摇杆、观察拖动、定位轻触、物件互动和自动行走中轻触停止，并说明双指、取消和旋转屏幕不会触发定位。
- 加载页轮播增加绿色定位提示；触控观察区的无障碍文案同步描述定位、互动与停止。
- 入场教学已改为准星下方的无底板 WebGL 焦点提示，不再显示旧键鼠图标组。桌面版用两行文字同时说明 WASD／方向键＋鼠标观察和绿色标记点击前往；触屏版优先说明绿色标记轻触前往，再补充左侧摇杆与拖动观察。提示保留暖白填充、平滑黑色描边和与场景一致的单枚绿色定位针，默认显示 9 秒，不更新截图基线。

## 模块与接口

- `src/navigation/player-navigation.js`
  - 导航表面射线求交。
  - 终点占位校验。
  - 不修改正式位置的直达路径模拟。
  - 实际移动与模拟共用内部步进规则。
- `src/navigation/point-walk-controller.js`
  - 管理候选、确认、移动、到达、阻挡和取消。
  - 候选查询上限 20 Hz；相机未变化时复用缓存。
  - 管理世界定位标记。
- `src/main.js`
  - 负责输入优先级、场景生命周期和手动／自动移动接管。
- `src/ui/webgl-hud.js`
  - 只增加自动行走停止提示和测试快照；没有方式选择或切换按钮。

## 验收重点

- 平地、沙地、教室、走廊、楼梯、斜坡、高台和多层平台能选中正确的最近导航面。
- 关闭的门、墙、栏杆、课桌、球架和校园边界不会被直达模拟穿过。
- 门框、楼梯边缘、窄走廊和课桌通道附近的无效落点会在光标半径 1 米内扫描，并吸附至 0.8 米内最近的合法同层位置。
- WASD／方向键、Shift、摇杆与定位行走同时可用，且接管时没有残余速度。
- 自动行走途中环视不改路线；点击／轻触只停止一次。
- 触摸覆盖轻触、慢拖、快速拖、拖回起点、双指、取消和横竖屏变化。
- 固定机位性能检查不得出现完整场景递归射线、热路径纹理上传或明显 p95 回退。
- 发布前运行 `npm run build`、`npm run perf:build`、`npm run build:test` 和相关 Playwright 测试；未经确认不更新截图基线。
