# Nintendo Game & Watch Fire FR-27 制作计划 v0.1

更新时间：2026-08-22
状态：Gate A–F 已完成，Fire FR-27 可玩运行时已接入；原机精确节拍继续作为后续录像校准项

## 1. 冻结范围

- 正式目标为 Nintendo Game & Watch `Fire` Wide Screen，型号 `FR-27`。
- 用户于 2026-08-22 明确用 Fire FR-27 替换此前候选 Helmet CN-07；Helmet 保留为后续候选，不参与本轮资产或规则。
- Silver Series `Fire RC-04` 是不同版本；MAME 资料将 FR-27 记为重写版本，不能混用其程序、画面或规则数据。
- `Fire Attack ID-29`、Elektronika 仿制版和后来的重制／Gallery 版本全部排除。
- 项目不依赖 ROM。MAME 只用于确认硬件和版本边界，不从 ROM 或模拟器资源复制玩法实现与液晶资产。

## 2. 当前已确认事实

- 用户主参考已归档为 `docs/references/handheld/fire/fire-fr27-user-layout-reference-v01.png`。
- 主机属于横向 Wide Screen 外形：左右各一个红色圆形操作键，右上为 `GAME A`、`GAME B`、`TIME` 功能键，并带 `ALARM`、`ACL` 小控制位。
- 面板标题为 `FIRE`，屏幕包含时间／得分数字、AM／PM、MISS、建筑火情、下落人物、底部救援者和右侧救护车构图。
- MAME 当前资料记录 FR-27 使用 Sharp SM5A、自定义固定段 LCD 和一位声音；声音能力可沿用 Octopus 的 SM5A 风格技术路线，但音型必须重新校准。

资料来源：

- [MAME `hh_sm510.cpp` 中的 FR-27 硬件和版本说明](https://github.com/mamedev/mame/blob/master/src/mame/handheld/hh_sm510.cpp#L1544-L1623)
- [用户主参考归档说明](../references/handheld/fire/README.md)

## 3. 当前工作值与后续校准项

- 外壳真实尺寸、厚度、按钮直径和 LCD 可视矩形。
- 外壳尺寸暂按 `124 × 70 × 10 mm`，LCD 工作矩形按正视底图推导；均为运行工作值。
- 77个物理段、四组可叠加烟雾电极、四位独立七段数字、状态文字、人物、担架、落地和右侧动作已冻结并进入运行图集。
- Game A／B 已提供两套速度曲线、三次 MISS、200/500 分清除 MISS、最高分存档和 Game Over；精确毫秒节拍仍待原机录像校准。
- 下落人物依据原机录像整理为连续三段接应路线；Game B 的较低楼层入口与精确节拍仍是候选工作值，不写成 ROM 或原机电极扫描事实。
- Fire 使用独立一位压电脉冲音型；频率和时值仍可随原机录音校准。
- 校园实例固定在 `b2-room-1-floor-2-row-5-column-2-student-desk` 左侧课桌格。

以上工作值不冒充原机实测；新资料到达时直接校准数据表和状态机。

## 4. 制作与接入顺序

严格遵循 `docs/plans/lcd-handheld-production-guide-v0.1.md`：

1. Gate A：继续补齐高分辨率原机照片、说明书和录像来源表。
2. Gate B：依据用户主参考只生成一张写实正交正视候选；完整四边、无透视、无手、无环境、无水印。用户确认前不扩展。
3. Gate C：从最初确认源一次制作正式底图，清除所有活动液晶，保留固定印刷、文字、玻璃和正常按钮。
4. Gate D：制作全亮图和人工分色所有权图；全段编号图、逐段联系表与重建指标全部通过后冻结物理段。
5. Gate E：建立 Fire 独立语义表和代表状态联系表，不复用 Octopus 段号或状态组合。
6. Gate F：接入写实底图、共享透明图集和 `enabled` BufferGeometry，在桌面、横屏和竖屏中校准。
7. Gate G：依据说明书与原机录像实现规则、节拍、声音、存档和完整回归。

## 5. 可复用边界

可以从 Octopus 抽取或复用：

- 写实底图与薄壳展示结构。
- 共享段图集、合并 BufferGeometry 和 `enabled` 属性更新。
- 按钮归一化坐标、扩大触摸区、多点所有权和按下反馈。
- WebGL 全屏 HUD、响应式安全区、退出恢复和尾随点击抑制。
- AudioContext 生命周期、版本化最高分存档和测试接口形态。

必须独立：

- `createFireHandheldGame` 控制器、Fire 配置和存档命名空间。
- 物理段清单、语义布局、状态机、碰撞表、节拍表、音型和专项测试。
- 校园实例、摆放点和轻量交互代理。

## 7. 运行实现与验证

- 共享透明图集只加载一次；LCD 由一个合并 `BufferGeometry` 的 `enabled` 属性控制，动画热路径不上传纹理。
- 支持实体红键、GAME A／GAME B／TIME、键盘、鼠标、多点触控、响应式说明、退出恢复和版本化最高分存档。
- 左上烟雾的物理源仍是 `segment.001`、`.002`、`.018`、`.034` 四组电极，但运行时以8种单片／多片组合循环；最浓一帧同时点亮四组，不再把四组错误地当成四张互斥画面。
- 下落人物使用三段连续路线：每段末端只在担架位与该段接应位一致时成功；成功显示担架承载姿势 `068／071／067` 并进入下一段，错过时才显示对应地面撞击姿势 `073／074／075` 和 MISS。
- 右侧消防员／救护车交接动画使用主体电极 `043` 与手脚局部电极组合显示，避免只出现零碎肢体而看不到完整消防员。
- 运行语义表已更新为 `fire-lcd-semantic-layout-v02.json`；77段物理图集与用户确认母图未改动。
- 专项 Fire 测试与既有 Octopus 回归共9项通过；`npm run build`、`npm run build:test`、`npm run perf:build` 均通过。
- 浏览器实际画面已检查：写实底图清晰，LCD 叠合位置正确，按键和退出命中区域处于可用范围。
