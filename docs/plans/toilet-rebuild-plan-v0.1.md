# 厕所整体重制计划 v0.1

日期：2026-09-01  
状态：完成技术评估；现有运行 GLB 保持不动，尚未开始制作替换模型

## 1. 结论

厕所不宜继续直接修改当前 `toilet-game-optimized-v01.glb`。现有运行资产没有可编辑的 Blender 源文件，主体、屏风、屋顶与旧化已经合并为单个网格／单个 primitive；直接在 GLB 上切割两片屏风墙，容易同时破坏 UV、手写“女／男”标识、墙面旧化、顶点法线与檐下通风结构。重做一个有语义分件、可持续修改的源模型，风险和总返工量更低。

替换模型获视觉确认前，当前 GLB、加载路径、碰撞体和不可进入边界全部保留，不制作临时布尔补丁，也不把新旧模型混接到正式运行场景。

## 2. 新模型必须保留

- 运行定位继续以中心约 `[5.34, -58.67]`、东西向约 `6 m`、南北向当前工作值约 `4.8 m` 为替换边界；尺寸仍是重建工作值，不是实测数据。
- 一层、低矮双坡黑瓦顶、无窗、连续檐下通风空隙和四周白灰砖柱。
- 背墙、左右侧墙和中央正墙的既有入口拓扑；女厕在左、男厕在右；小型褪色手写标识的方向与位置关系。
- 更破旧的石灰墙、局部露砖、潮湿青苔和当前校园水彩材质方向。
- 继续作为不可进入建筑，沿用约 `6 × 4.8 m` 的简化整体碰撞边界，不制作内部厕位、排水或交互。

## 3. 本轮新增校准目标

- 两片南侧屏风墙应比当前模型更短。
- 校准时同时满足：从校园正面不能直看男女两端门洞；站在内部门口位置，可以斜向看见操场。
- 屏风墙的具体长度、内端位置和斜视角仍未知。第一轮灰盒只做候选，不把截图笔画当作量尺。
- 建议先试约 `1.5–1.7 m` 的单片墙长、约 `2.2–2.5 m` 的中央净开口；这些仅为画面比较起点，不能写成历史尺寸。

## 4. 制作与资产结构

1. 在 Blender 新建可编辑源文件，按主体墙、两片屏风、檐下柱、屋顶、文字标识和旧化层分件命名。
2. 第一阶段只做无材质灰盒，输出俯视、南立面、左右斜视和两个门口向操场的视线图。
3. 亲历者确认墙长与视线后再制作黑瓦、旧石灰、露砖、青苔和小字，不提前细化内部。
4. 发布资产仍以低 draw call 为目标：作者源保留语义分件，最终导出可合并为一个主要网格和一套贴图；不得增加 LOD 或低模替代路径。
5. 保留当前 GLB 作为回退，候选使用新文件名和版本号；通过运行画面确认后才切换正式加载 URL，并按现有保守参数做 Meshopt 压缩。

## 5. 验收门槛

- Gate A｜结构灰盒：外轮廓、入口拓扑、屏风长度和两条门口斜视线获确认。
- Gate B｜材质模型：前、后、左右和门口斜视均检查；通风带连续，文字不镜像，墙面旧化不重复拉伸。
- Gate C｜运行接入：手机第一人称比例、阴影、轮廓、整体碰撞和厕所／沙池净距无回归。
- Gate D｜工程验证：`npm run build:test`、定向场景测试、`npm run build` 和 `npm run perf:build` 通过；用户确认实际运行画面后才允许更新视觉基线。
